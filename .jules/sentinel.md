## 2024-11-08 - [Hardcoded Verification Tokens & JWT Weak Signature]
**Vulnerability:** Found hardcoded verification tokens (a1b2c3d4e5f60718293a4b5c6d7e8f90123456789abcdef0) used for agreement and deed signing endpoints, alongside a weak JWT signing implementation in server.ts that lacked proper cryptographic integrity, making the tokens vulnerable to trivial forgery.
**Learning:** The application was directly embedding static, predictable tokens for sensitive operations, completely defeating the purpose of verification tokens, and its JWT implementation was mocking signatures via string concatenation instead of utilizing a secure cryptographic hash (HMAC-SHA256). Both issues significantly compromise document authenticity and API access control. Also learned that when providing fallback secrets for JWTs, they must be hoisted to module level or otherwise persist for the lifetime of the application, else the backend will reject validly signed tokens generated by itself previously.
**Prevention:** Utilize cryptographically secure random number generators (e.g., crypto.randomBytes) for dynamic token generation, and enforce correct server-side HMAC-SHA256 algorithms with environment-managed secure secrets (e.g., process.env.JWT_SECRET) or process-long fallback constants for all JWT signing operations.
