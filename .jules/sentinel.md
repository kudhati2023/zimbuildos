## 2026-10-09 - Fail Securely: Hardcoded HMAC Secret Fallbacks
**Vulnerability:** Core system modules (`security_guard.py`, `fleet_appraisal_manager.py`, `hr_payroll_manager.py`, `field_service_manager.py`) were using `os.environ.get("ZIMBUILD_HMAC_SECRET", "zimbuild-secure-erp-signing-key-2026")`. This meant if the environment variable was missing (due to misconfiguration), the system would silently fall back to a hardcoded string to compute cryptographic signatures.
**Learning:** This violated the "Fail Securely" principle. A misconfigured environment in production would silently use a well-known default key, completely compromising the tamper-evidence of our audit logs, work orders, and digital seals. Security controls must fail closed, not open.
**Prevention:** Critical cryptographic secrets must NEVER have a hardcoded fallback string in `os.environ.get()`. Always fetch the variable and explicitly raise a `ValueError` if it is `None` or empty, forcing the deployment to fail loudly until properly secured.
